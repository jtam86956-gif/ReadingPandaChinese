# Panda News（熊猫新闻）产品需求文档（PRD）

> 一个「通过阅读真实中文资讯学习中文」的产品，借鉴 `hehonghui/awesome-english-ebooks` 的「内容流水线 + Git 分发」模式。
>
> 版本：v0.1（MVP 规划）｜日期：2026-11-12｜状态：草案

---

## 1. 背景与目标

### 1.1 背景
- `awesome-english-ebooks` 证明了一个模式成立：**用 Calibre 自动抓取外刊 → 转多格式 → Git 仓库分发 → 配合阅读器**，为英语学习者提供持续、免费、零摩擦的真实阅读材料，收获数万 Star。
- 中文作为第二语言（CSL，Chinese as a Second Language）的学习市场缺少同类产品：现有材料要么是教材体（枯燥、非真实语境），要么散落在各新闻站（无注音、无分词、无翻译、无生词管理），学习闭环断裂。
- 大模型（LLM）与中文 TTS 的成熟，让「逐句讲解、自动注音、智能分级」的成本降到可以产品化。

### 1.2 产品目标
1. **持续供给**：自动化流水线每日产出带注音、分词、翻译、音频的真实中文阅读材料。
2. **沉浸阅读**：阅读器支持「点字出拼音/释义/笔顺、点词查义、整句翻译与 AI 讲解、朗读」。
3. **学习闭环**：生词本 + 间隔重复（SRS）复习 + 学习统计，形成「读 → 记 → 复习 → 测」闭环。
4. **低冷启动成本**：内容仓库天然免费托管，MVP 阶段不做重后端，先验证内容与阅读体验。

### 1.3 非目标（MVP 阶段不做）
- 不做社区/社交（评论、关注、打卡分享）。
- 不做 UGC（用户上传内容）。
- 不做直播课 / 真人外教。
- 不做写作批改、口语评测（留待后续版本）。

## 2. 产品定位与一句话价值

**定位**：面向中文学习者的「真实语境分级阅读器 + 生词复习系统」。

**一句话价值**：*每天一篇你读得懂的真实中文——点一下就会，读着读着就记住了。*

**对标关系**：

| 维度 | awesome-english-ebooks | Panda News（本产品） |
|---|---|---|
| 学习者 | 中国人学英语 | 全球中文学习者（CSL）+ K12 语文提升 |
| 内容 | 英语外刊（经济学人等） | 中文资讯 / 公版经典 / 分级短文 |
| 仓库角色 | 内容分发（只读下载） | 内容分发 + 元数据索引（被 App 消费） |
| 阅读器 | 第三方（英阅阅读器） | 自研（Web 优先 → App） |
| 学习辅助 | 无（阅读器侧提供） | 内置：注音/分词/翻译/AI 讲解/生词本/SRS |

## 3. 目标用户与画像

### 3.1 核心用户：中文作为第二语言学习者（CSL）
- **HSK 2–5 级考生**：需要真实语境输入，教材不够。
- **海外华人子女**：家长希望维持中文阅读能力，缺合适材料。
- **中国文化 / 时事爱好者**：想直接读中文原文，而不是翻译稿。
- **来华工作/留学的外国人**：需要快速提升实用阅读。

### 3.2 次级用户：K12 语文与通识提升
- 小学高年级–初中生：拓展阅读、积累词汇。
- 家长：为孩子挑选分级读物。

### 3.3 用户画像（典型）
> **Lisa，28 岁，美国人，在上海工作，HSK 4 级。**
> 每天通勤 30 分钟，想读真实中文但《人民日报》太难、教材太无聊。她希望：打开 App 有一篇「刚好够得着」的短文，点不认识的字能立刻看到拼音和意思，遇到的生词自动收进生词本，第二天复习。

> **陈先生，40 岁，温哥华华人，女儿 10 岁。**
> 想让女儿保持中文阅读，需要按难度分级、带拼音、有朗读音频的材料，最好是孩子感兴趣的话题（动物、科学、故事）。

## 4. 核心场景与用户旅程

### 4.1 核心场景
| # | 场景 | 触发 | 期望结果 |
|---|---|---|---|
| S1 | 每日一读 | 用户打开 App | 推荐 1–3 篇匹配其等级的短文，5–10 分钟读完 |
| S2 | 读懂难字 | 阅读中遇到生字 | 点字 → 拼音、释义、笔顺、组词、例句 |
| S3 | 读懂难句 | 句子看不懂 | 点句/选句 → 整句翻译 + AI 语法讲解 + 朗读 |
| S4 | 积累生词 | 想记住这个词 | 一键加入生词本，自动记录上下文 |
| S5 | 复习巩固 | 生词本有积累 | SRS 推送复习卡片，记住/忘了标记 |
| S6 | 追踪进步 | 想看到成长 | 学习统计：阅读篇数、时长、生词掌握数、等级曲线 |
| S7 | 离线/多端 | 通勤无网 | 已读/已下载内容离线可用；进度多端同步 |

### 4.2 主用户旅程（S1→S2→S4→S5）
```
打开 App → 今日推荐 → 选一篇 → 沉浸式阅读
  → 遇生字：点字看拼音/释义 → 遇生词：加入生词本
  → 遇难句：整句翻译/AI 讲解 → 读完 → 统计更新
  → 次日：SRS 提醒复习昨日生词 → 继续读新一篇
```

## 5. 功能需求

按模块组织，优先级采用 **MoSCoW**：Must（必须）/ Should（应该）/ Could（可以）/ Won't（暂不）。

### 5.1 内容供给（系统侧，用户无感知）
| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| C-01 | 新闻 RSS 自动抓取 | Must | 每日定时抓取合规中文新闻源，去重、清洗正文 |
| C-02 | 公版/分级内容入库 | Must | 公版经典 + 自建分级短文，按等级组织 |
| C-03 | 中文 NLP 加工 | Must | 注音（pypinyin）、分词、词性、难度分级（HSK/字频） |
| C-04 | 翻译生成 | Must | 生词中英释义、整句英译（词典 + LLM） |
| C-05 | TTS 音频生成 | Should | 每篇生成标准普通话朗读音频（整段 + 分句） |
| C-06 | 多格式产物 | Should | 每篇输出 `.json`（结构化，供 App）+ `.epub`（带注音）+ `.pdf` |
| C-07 | 内容审核 | Should | 敏感词/合规过滤（资讯源尤其重要） |
| C-08 | 内容目录 API | Must | 按日期/等级/分类列出文章、取单篇 manifest |

### 5.2 阅读器（核心体验）
| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| R-01 | 沉浸式正文阅读 | Must | 排版舒适，字号/行距/主题可调，支持竖排（可选） |
| R-02 | 点字查义 | Must | 点汉字 → 拼音（带声调）、释义、部首、笔画数 |
| R-03 | 笔顺动画 | Should | 生字笔顺动画展示（汉字描红数据） |
| R-04 | 点词查义 | Must | 点词 → 分词结果、词典释义、词性、例句 |
| R-05 | 整句翻译 | Must | 选句/点句 → 英文翻译（或目标语） |
| R-06 | AI 句子讲解 | Should | LLM 讲解该句语法点、难点词、同义表达 |
| R-07 | 注音开关 | Must | 全文注音可一键开/关；可只给生字注音 |
| R-08 | 朗读（TTS） | Must | 点读单字/词/句，或整篇播放，可调语速 |
| R-09 | 阅读进度记忆 | Must | 自动记录读到哪，多端同步 |
| R-10 | 划线/笔记 | Should | 高亮句子、写笔记 |
| R-11 | 难度调节 | Could | 阅读中临时「简化/扩写」当前段落（LLM） |

### 5.3 生词本与复习（学习闭环）
| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| V-01 | 加入生词本 | Must | 从阅读中点词一键加入，附带原句上下文 |
| V-02 | 生词本管理 | Must | 列表、搜索、按掌握度筛选、删除 |
| V-03 | SRS 复习 | Must | 间隔重复卡片：显示中文 → 回忆 → 翻面看释义；标记「认识/模糊/忘了」 |
| V-04 | 复习提醒 | Should | 每日定时推送待复习数量 |
| V-05 | 生词听写/选择练习 | Could | 从生词本生成选择题、听音选词 |
| V-06 | 掌握度统计 | Should | 生词掌握率曲线 |

### 5.4 发现与推荐
| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| D-01 | 今日推荐 | Must | 基于用户等级 + 兴趣标签推荐 1–3 篇 |
| D-02 | 分类浏览 | Must | 按话题（时事/科技/文化/故事/经典）、等级筛选 |
| D-03 | 等级测试 | Should | 入门做简短测试定初始等级（可选跳过） |
| D-04 | 搜索 | Should | 全文检索文章 / 搜词查出现文章 |
| D-05 | 收藏 | Should | 收藏文章，稍后读 |

### 5.5 账户与同步
| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| A-01 | 账户体系 | Should | 邮箱/第三方登录（MVP 可先本地，同步延后） |
| A-02 | 多端同步 | Should | 生词本、阅读进度、设置云端同步 |
| A-03 | 离线阅读 | Could | 下载文章离线读 |

### 5.6 学习统计与激励
| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| G-01 | 学习统计 | Should | 阅读篇数/时长、生词新增与掌握、连续天数（streak） |
| G-02 | 等级成长 | Could | 虚拟等级/徽章，基于阅读量与生词掌握 |

## 6. 内容策略

### 6.1 内容来源（合规优先，规避 DMCA 风险）
| 来源类型 | 具体来源 | 版权处理 | 优先级 |
|---|---|---|---|
| 公版书 | 四书五经、鲁迅、老舍、沈从文等（作者逝世 >50 年） | 公有领域，自由使用 | 高 |
| 公开新闻 RSS | BBC 中文、联合早报、端传媒（部分）、德国之声中文等 | 遵守 robots 与转载政策，仅摘要+链接/或抓正文自用 | 高 |
| 政府/机构公开 | 新华社、人民日报 RSS | 注明来源，不做商用改编 | 中 |
| CC 授权内容 | 维基文库、CC-BY 博客 | 按授权署名 | 中 |
| 自建内容 | 编辑/AI 生成的分级短文 | 自有版权 | 中（差异化核心） |
| 播客音频 | 公开 RSS 或 TTS 生成 | TTS 自有；播客注明来源 | 低 |

> **红线**：不抓取《经济学人》中文版、财新、端传媒付费墙等受版权保护的付费内容；不全文转载商业媒体。资讯类优先用 RSS 摘要 + 原文链接，正文抓取仅限明确允许的源。

### 6.2 难度分级
采用 **HSK 词汇覆盖 + 字频** 双维度，输出 6 级（对应 HSK 1–6）：
- 计算文章中 HSK 各级别词汇覆盖率 + 平均句长 + 生僻字比例 → 映射到等级。
- 每篇打 `level` 标签（1–6）+ `vocab_level`（核心生词所属 HSK 级）。

### 6.3 内容清单结构（每篇）
```json
{
  "id": "news_20261112_001",
  "title": "中国新能源汽车出口再创新高",
  "source": "xxx",
  "source_url": "https://...",
  "published_at": "2026-11-12",
  "level": 4,
  "category": "科技",
  "tags": ["新能源", "汽车"],
  "word_count": 380,
  "content": [
    {
      "sentence_id": "s1",
      "text": "中国新能源汽车出口再创新高。",
      "pinyin": "zhōng guó xīn néng yuán qì chē chū kǒu zài chuàng xīn gāo 。",
      "translation": "China's new energy vehicle exports hit a new high again.",
      "tokens": [
        { "w": "中国", "pos": "n", "hsk": 3, "meaning": "China" },
        { "w": "新能源", "pos": "n", "hsk": 5, "meaning": "new energy" }
      ],
      "audio_url": "https://.../s1.mp3"
    }
  ],
  "audio_url": "https://.../full.mp3",
  "new_vocab": [ { "w": "创新高", "hsk": 6, "meaning": "...", "example": "..." } ]

```

```
├── 正文：沉浸式排版
└── 底部：进度条 / 上一篇下一篇
```

## 8. 学习闭环设计（核心差异化）

```
阅读（输入） ──点词──▶ 生词本（记录上下文）
   │                      │
   │                      ▼
   │                  SRS 复习（间隔重复）
   │                      │
   ▼                      ▼
 统计反馈 ◀────────── 掌握度更新
   │
   ▼
 推荐更难/更匹配的内容（难度自适应）
```

- **SRS 算法**：采用简化版 SM-2（与 Anki 同源），间隔：1d → 3d → 7d → 14d → 30d，根据反馈（认识/模糊/忘了）调整。
- **上下文记忆**：每个生词永远绑定「第一次遇到它的那句话」，复习时可跳回原文重读——这是真实语境学习的关键。

## 9. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 阅读器首屏 < 1.5s（Web）；点字响应 < 200ms；整篇加载 < 2s |
| 可用性 | 支持简体中文；UI 支持中/英双语切换（照顾外国用户） |
| 离线 | 已下载内容可离线阅读；生词本本地优先、云端同步 |
| 兼容 | Web：Chrome/Safari/Edge 近 2 年版本；移动端：iOS/Android（后续） |
| 数据 | 生词、进度每日备份；支持导出生词本（CSV/Anki） |
| 合规 | 内容版权合规；用户数据隐私（不售卖）；未成年人模式（K12） |
| 成本 | MVP 阶段月度基础设施成本 < ¥300（详见技术选型文档） |

## 10. 成功指标

### 10.1 北极星指标
**周活跃学习者中，完成「阅读 ≥ 1 篇 + 复习 ≥ 1 次」的用户数（WAU 闭环完成率）。**

### 10.2 分层指标
| 阶段 | 指标 | 目标（MVP 后 3 个月） |
|---|---|---|
| 获客 | 内容仓库 Star / 访问量、App 新增 | 内容仓 1k Star；App 1k 注册 |
| 激活 | 首日阅读 ≥ 1 篇的比例 | ≥ 50% |
| 留存 | 次日留存 / 7 日留存 | 次留 ≥ 35%，7 留 ≥ 20% |
| 闭环 | 人均生词本周新增 / 复习完成率 | 周新增 ≥ 8 词；复习完成率 ≥ 60% |
| 阅读 | 人均周阅读篇数 / 时长 | ≥ 3 篇 / ≥ 20 分钟 |

## 11. 里程碑与版本规划

| 阶段 | 周期 | 交付 | 验证目标 |
|---|---|---|---|
| **M0 内容流水线验证** | 第 1–2 周 | Calibre 抓中文新闻 + pypinyin 注音 → 生成 epub/json → 推 Git 仓库 | 能稳定每日产出内容 |
| **M1 MVP 阅读器** | 第 3–5 周 | Web 阅读器：读 Git raw JSON、点字拼音/释义、点词查义、整句翻译、注音开关 | 核心阅读体验可用，找 10–20 个种子用户试用 |
| **M2 生词本 + SRS** | 第 6–8 周 | 生词本、SRS 复习、学习统计、账户与同步 | 学习闭环跑通，验证留存 |
| **M3 内容扩充 + AI** | 第 9–12 周 | 公版经典入库、分级短文、AI 句子讲解、TTS 音频、搜索 | 内容厚度 + 体验提升 |
| **M4 多端 + 增长** | 第 13 周+ | App（iOS/Android）、分享、推荐优化 | 规模化 |

> 每个里程碑结束做一次用户访谈（≥ 5 人），决定下一步优先级。

## 12. 风险与待决问题

| # | 风险/问题 | 影响 | 应对 |
|---|---|---|---|
| R1 | 资讯内容版权（DMCA） | 高：仓库/服务可能被下架 | 优先公版 + RSS 摘要 + 自建；全文抓取仅限允许源；署名 |
| R2 | GitHub 仓库膨胀（二进制） | 中：触发体积限制、克隆慢 | 大文件走 Git LFS 或对象存储，Git 只存 JSON 元数据 |
| R3 | raw.githubusercontent.com 限流 | 中：App 拉取失败 | 加 CDN/自建对象存储做镜像；带缓存 |
| R4 | LLM 成本与延迟 | 中：AI 讲解贵且慢 | 高频释义走本地词典；AI 讲解限难句、按需触发 + 缓存 |
| R5 | 中文 NLP 准确率 | 中：注音/分词错误影响体验 | 用成熟库（pypinyin + jieba/pkuseg）+ 人工抽检关键内容 |
| R6 | 用户冷启动（无内容偏好） | 低 | 默认按 HSK 3–4 推；提供等级测试；可手动调 |
| Q1 | 商业模式？（MVP 不解决） | — | 先做免费 + 内容开放，验证后考虑：会员去广告/无限 AI、内容授权给机构 |
| Q2 | 是否支持繁体 / 方言 / 粤语？ | — | MVP 只简体普通话；繁体作为阅读设置项（opencc 转换）后续加 |
| Q3 | K12 与 CSL 是否分两个入口？ | — | MVP 共用内容池，靠等级与话题区分；后续可独立 Kids 模式 |
